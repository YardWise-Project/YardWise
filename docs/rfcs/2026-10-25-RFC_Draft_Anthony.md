## Problem and Context 
 

We as a team need to decide whether we keep developing our application as a Mobile Application, or if we need to divert to developing a Web Application. This decision needs to be decided now because if we develop YardWise on the basis that it is going to be a mobile application, then we as a team may run into issues with launching the mobile app on Google Play and Apple store. 

If we decide to do nothing about this decision now, then we can develop the backend of the application. Although there is going to come a time where we have to identify whether YardWise is going to be a Web-based Application, or a Mobile-based application. 
 
## Options 
 
At least three options, **including "do nothing"**. Give each option a short name, an account of its real costs, and the condition under which it would be the right choice. An option with no such condition is a strawman, and a strawman weakens the whole document. 
 
### Option A: Web Application 
 
A Web Application would have YardWise launch on computers via the internet instead of users utilizing our application through mobile stores, e.g., Google Play, and Apple Store. Developing a web application would give the team an easier developing experience by directly seeing our application through our computers. The costs here are relatively low compared to launching a mobile application.  
 
### Option B: Mobile Application 
 
A Mobile Application would have YardWise launch through mobile application store, e.g., Google Play and Apple Store. Developing a mobile application would be more difficult as well by accounting for different mobile devices, as well as the age of the device operating system. The team would also have to research the necessities of launching a mobile applications, i.e., the costs of launching through Google Play and Apple Store. 
 
### Option C: Do Nothing 
 
If we decide to do nothing and table this decision for a later day then front-end development would be placed on hold. Although, back-end development could immediately begin, e.g., API and Database. This could hinder us later with improper programming connecting both front-end and back-end. This is the most unidealistic option. 
 
## Analysis 
 

A web-based application shows little to no cost and would give the team the opportunity to start programming both front-end and back-end for the application. A mobile-based application would be more difficult for programming for mobile devices and taking into account for legacy operating systems. Also, there would be a very possible obstacle with launching the application onto mobile stores. Finally, not making a decision would throw the team into a limbo status, where the only thing we would be able to work on is the back-end of our application. Again, this is the most unidealistic decision and recommend against not making a decision. 
 
## Recommendation and Verification Plan 
 
I would recommend Option A: Web Application. This would give the team an easier time for development compared to what development would look like for a mobile application. There would also be an easier launch of our application. Although, if we develop a finished product early, and time allots, we can also develop a mobile application that is relatively the same as our already finished web application. 

 

## Constraints 
 
Licensing, data use, IP, and the partner confidentiality boundary as they bear on this decision. If none apply, say so explicitly and briefly explain why.  

The only constraints I can see us possibly running into is licensing. In order for YardWise to launch we need to research what we need to work towards for licensing purposes. We as a team should start looking into this for both web-based application and mobile-based application.
